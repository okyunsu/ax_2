# PRD — 채용대행 AX 시스템

> 상태: 골격 (M0 검증 후 오케스트레이터가 재작성)
> 최종 수정: 2026-11-07

## 1. 배경과 문제
- 계획서 1건 작성에 보통 하루가 걸린다.
- 가장 큰 병목은 서식 오류 수정 — 조판보기로 띄어쓰기·표 크기를 일일이 맞추는 작업.
- 첫 계획서가 나오면 이후 문서(전형별 계획서·결과보고서)는 대부분 복붙이다.
- 과업목적은 보통 과업지시서에서 가져온다.

## 2. 목표
- 공고문·과업지시서 입력 → 서식이 맞는 문서 초안 자동 생성
- 담당자는 내용 검토·보완에 집중하고 서식 조정 시간을 없앤다.

## 3. 범위
### 포함
| 단계 | 내용 |
|---|---|
| M0 | 기술 검증: 서식 출력(B) → 입력 파서(A) → AI 추출(C) |
| M1 | 데이터 모델·API 계약 확정, 최소 전체 흐름 연결 |
| M2 | 수행계획서·전형별 계획서·결과보고서 생성 |
| M2.5 | Notion 단방향 게시 |
| M3 | 교육자료 3종 (서류위원·감독관·면접위원) |

### 제외 (현재)
- 결과보고서의 종합집계표·사진 입력 (틀만 생성, 내용은 담당자 작성)
- 기관별 원본 서식 완전 보존 (통일 서식 출력 허용)
- Notion → 시스템 역방향 동기화

## 4. 입력·출력
### 입력
- 공고문 (PDF / HWPX / HWP)
- 과업지시서
- 교육자료용: 일정·장소·인원은 사용자가 직접 입력

### 출력
- 계획서·결과보고서: HWPX (필요 시 DOCX)
- 교육자료: PPTX / HWPX (기존 서식 사용 또는 새 서식)
- 예시 서식은 종류별 폴더(계획서 / 결과보고서 / 교육자료)에 보관

## 5. 처리 구조
```
입력 문서 → [변환] MD/JSON → [AI 추출] 구조화 JSON → [사용자 검수·승인]
         → [템플릿 치환] HWPX/DOCX/PPTX
         → [Notion 게시] 승인된 사업 정보 (M2.5)
```

## 6. Notion 연동 방침 (M2.5)
- 기존 프로젝트·프로젝트 일정·업무 관리 DB와 템플릿 유지
- 승인한 사업 정보만 단방향 게시
- 기본 일정: 원서접수·서류·필기·면접 (인성검사는 필기에 포함)
- 담당자 매핑: 임시 방식으로 시작

## 7. 마일스톤별 완료 기준
| 단계 | 완료 기준 |
|---|---|
| M0-B | 결과보고서 템플릿 치환본을 한글에서 열었을 때 표 크기·줄 간격이 원본과 동일 |
| M0-A | 공고문 3~5건 변환 시 텍스트 누락 없음, 일정표·배점표 구조 유지 |
| M0-C | 수기 정답 대비 핵심 필드(과업목적·일정·인원) 추출 정확도 기록 |
| M1 | 공고문 1건 → 계획서 껍데기 1건 생성까지 전체 흐름 동작 |
| M2 | (M1 후 작성) |
| M2.5 | (M1 후 작성) |
| M3 | (M1 후 작성) |

## 8. 기술 결정
- 웹앱, 프론트 React, 백엔드 Python
- 개발 환경: Claude Code 데스크톱 앱, 로컬 PC, git (실제 자료·파생물은 커밋 제외)
- API 키·샘플 경로는 `.env`
- 입력 변환: MarkItDown, hwpx-tomd, markitdown-hwp (M0-A에서 비교 후 확정)
- 출력: python-hwpx 계열 (M0-B에서 검증 후 확정)
